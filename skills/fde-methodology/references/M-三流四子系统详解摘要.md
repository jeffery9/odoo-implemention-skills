## 1. 阅读约定与核心命题（〇）

| 记号 | 含义 |
|---|---|
| 触发 | 激活流程/子系统的事件或节律 |
| 步骤 | `V` 价值流、`W` 工作流、`K` 资产流、`P` 组合、`D` 发现、`E` 工程、`L` 学习 |
| 门 Gate | 必须取得证据才能通过的控制点，G0–G4 |
| 制品 Artifact | 步骤的可检验产出，**流程之间唯一的交接载体** |
| 交接口 Interface | 两子系统之间的交接点 ①–⑪（全表 §5.2.2），含反向/回流/旁路 |
| 回退 | 门未通过时的退回、挂起、终止路径 |

**核心命题**：三流与四子系统的失效，很少因为某一环「做得不好」，而多因**接缝失守**——
上游未交付可判定的制品，下游只能凭印象推进。故每个流程都列输出契约与失效模式。

## 2. 三流总纲（§1）

| 流 | 起点 → 终点 | 自然节奏 | 主指标 |
|---|---|---|---|
| 价值流 | 客户需求事件 → 可衡量业务改善被证实 | 月—季（跨项目/多发布） | Lead Time、TtV、价值实现率 |
| 工作流 | 工作项进入待办 → 部署并通过运营验证 | 周—Sprint（2 周） | 流速效率、WIP、缺陷逃逸率 |
| 资产流 | 一线经验产生 → 资产被复用或产品化 | 月—季（滞后） | 复用率、资产验证率、复用价值贡献 |

**三条高频误读（§1.2）**：① 价值流不能按部门切分；② 资产流不是第二条客户价值流；
③ 三流不是「在四子系统之间传棒」——每条流多数步骤**停在同一子系统内连续完成**，
且 11 个交接口里有 4 条是反向/回流。**三流不可用同一套指标考核。**

**三条结构性张力与预置取舍规则（§1.3）**：

| 冲突 | 短期诱惑 | 预置规则 |
|---|---|---|
| 赶价值流节点 vs 资产化 | 跳过捕获 | 每 Sprint 预留固定资产化额度（起步 10–15%），不可被交付挤压 |
| 资产化优先 vs 客户价值 | 打磨通用组件前置 | 只在「已在 ≥2 场景验证」后启动 |
| 工作流局部最优 vs 价值流 | 追吞吐/利用率 | 以 TtV 与流速效率为准，不以吞吐或利用率为考核 |
| 资产复用 vs 客户语境 | 直接复用省定制 | 复用必须附「适配清单 + 不适用情形」，缺失即不得复用 |

> 张力无法「平衡」，只能**预置规则**；临场平衡总是短期目标胜出。

## 3. 价值流七步 V1–V7（§2）

```
V1 选定价值单元 → V2 现状建图 → V3 量化七类损耗 → V4 未来态设计
→ V5 交接标准化 → V6 流动运营 → V7 价值实现校验 →（季度回到 V2 再建图）
```

- **V1 价值单元句式**：`[谁] 的 [什么业务指标] 在 [时间窗 T] 内从 [基线 A] 改善到 [目标 B]，以 [测量方式 M] 验证`。
  写不出这句即价值单元未定义，不应启动建图（否则画出的是活动图，不是价值流图）。
- **V2** 标注活动/交接/决策点/系统边界/信息流，每步记录处理时间与等待时间。
- **V3 七类损耗**：工作等待、决策延迟、交接摩擦、WIP 堆积、返工、采纳受限、价值未达成。
- **V4** 四类动作：消除 / 合并 / 并行 / 前置；输出目标 Lead Time、目标流速效率、需增删的交接点。
- **V5 交接契约四要素**：输入内容、验收标准、承诺时限、退回条件。缺任一项即为摩擦源。
- **V6** 看板可视化、拉式启动、WIP 上限、异常 24h 升级；**不引入新方法，只保证 V4 被执行**。
- **V7** 判定达成 / 部分达成（偏差归因）/ 未达成（修正假设或终止）；**价值流图有效期约一季度**。
- **度量（§2.5）**：Lead Time **报 P50 与 P90**（只报均值掩盖长尾）、TtV（与 Lead Time 不可混用）、
  流速效率（<25% 说明等待是主成本）、交接次数、返工率、价值实现率。
- **失效（§2.6）**：画成部门流程图（按组织边界切分）、图做完挂墙上（无 V6/V7）、
  **项目验收即宣布价值实现**（缺 V7 基线对照）、只优化单一环节。

## 4. 工作流六步 W1–W6（§3）

- **状态机（§3.2）**：Backlog → Ready(DoR) → In Progress → In Review/Test → Done(DoD)
  → Deployed → Verified(运营验证) → Archived；含回退/修复支路。
  作用不是增加审批，而是让「卡在哪一步」一眼可见。
- **W1 六锚点**（§10.4 操作化）：客户问题 · 价值假设 · 价值流活动 · 技术成果 · DoD · 验证证据。
  **六项缺任一，不得进入 Ready**。
- **W2 DoR**：验收标准可判定、依赖已清空、证据取得方式已定。
- **W3 切片**：**纵向切片**（端到端可观察），禁止按技术层横向拆分；容量按历史流速，不按人数。
- **W4 在制控制**：拉式启动、每列 WIP 上限、单一 owner、阻塞 24h 升级。
- **W5 四道质量门**（§3.6 与 G0–G4 映射）：

| [M] 编号 | 门名 | [F] §10.5 对应 | 位置 |
|---|---|---|---|
| G0 | 组合门 | —（本篇新增） | 机会进入组合前 |
| G1 前段 | 问题验证门 | 问题验证门 | 发现阶段末 |
| G1 后段 | 方案就绪门 | 方案就绪门 | 立项裁定 |
| G2 | 交付质量门 | 交付质量门 | 部署前 |
| G3 | 价值实现门 | 价值实现门 | 上线后 30–90 天 |
| G4 | 资产门 | —（§11.4 有评估项，本篇显式化） | 资产入库前 |

  > 2.0 的四道门在工作流内部；本篇在两端各加一道跨流门。**不是两套口径，是同一门禁体系的完整化。**
- **W6 证据包七项**：部署记录、配置基线、测试与压测结论、监控告警配置、异常处置手册、
  回滚步骤、已知限制清单。交接判据：客户运维方可独立完成一次「故障注入 → 恢复」；同时触发 K1。
- **Sprint 合格产出五类**（§3.5）：已验证技术假设 / 可运行集成 / 可部署能力 / 运营改善 /
  可度量瓶颈削减。只能说出「完成 X 个任务」即未产生可验证增量。
- **追溯链检验**：随机抽 5 个工作项，任一无法在 2 分钟内回溯到客户问题，链条已失效。
- **度量**：流速效率、WIP、吞吐（单独看会诱导做小活）、DoR/DoD 达成率、缺陷逃逸率、阻塞时长中位数。
- **失效**：全员忙碌但交付慢（优化利用率）、技术债累积（无 ADR/回滚）、交付多价值少（Output 替代
  Outcome）、追溯链形同虚设（工作项只写「修复 bug」）。

## 5. 资产流六步 K1–K6（§4）

```
K1 结构化捕获 → K2 跨项聚类 → K3 资产验证(G4) → K4 封装复用
→ K5 版本/归属/退役 → K6 产品化 → 复用收益与失败教训回灌 K1
```

- **K1 五要素**：情境、做法、结果证据、适用边界、**不适用情形**（缺后者在复用时几乎必然同样失败）。
- **K2**：≥2 场景重复且有效才进候选；单场景标记为个案。
- **K3 三硬判据**：复现性（≥2 不同客户场景独立生效）、可迁移性（去客户专有依赖 + 适配点清单）、
  可维护性（owner + 版本 + 维护 SLA）；再过 [F] §11.4 八项评估。未过 → 降级为「参考模式」
  （可检索、不可承诺）。
- **K4**：封装为组件/代码库、基准与评测集、模板与流程、领域知识与判定规则；
  必须配**复用说明书**（适用条件、适配步骤、已知限制、集成成本）。
- **K5**：owner 必须是**人**、版本号、变更记录、弃用策略。无 owner 的资产 12 个月内必然腐化。
- **K6 产品化四条件同时满足**：≥3 客户稳定复用 · 客户愿单独付费 · 标准交付路径 · 毛利高于项目制；
  产品化后仍须保留客户语境适配层。
- **资产成熟度**：A0 草稿（单场景）/ A1 候选 / A2 已验证（≥2 场景 + 适配说明）/
  A3 可规模化（≥3 场景 + SLA 版本）/ A4 产品化 / A5 退役冻结。
- **度量**：复用率、资产验证率、**复用价值贡献（配平复用率）**、知识捕获覆盖率、边际交付成本。
- **失效**：资产库大没人用（无说明书/owner）、同一坑反复踩（只留成功案例）、
  复用在新客户失败（缺不适用情形）、全员做产品化客户无人管（误把资产流当价值流）。

## 6. 三流 × 四子系统（§5.1–5.2）

- **关键结论**：不是两套模型，是同一系统的两个切面——**四子系统是「谁管」，三流是「管什么在流动」**。
- 工程执行是工作流主体，组织学习与资产是资产流主体，但**两者都不独占**；
  组合管理与发现与评估共同覆盖价值流前段与选择面。
- **内聚度差异**：价值流 7 步跨 4 个子系统、每步换手；工作流 6 步中 4 步连续在工程执行内；
  资产流 6 步几乎全在组织学习子系统内。
- **11 个交接口** = 主循环 5（①–⑤）+ 流特有 6（⑥–⑪），其中 **⑦⑨⑩⑪ 是反向/旁路/回流**；
  传棒模型漏掉的正是这 4 条，而它们承载三流咬合的全部价值。

## 7. 四子系统与接口契约（§6）

| 子系统 | 回答 | 主制品 | 主指标 | 节奏 |
|---|---|---|---|---|
| 组合管理 | 该追什么 | 组合看板、评分卡、产能预算 | 组合价值密度、终止及时率 | 双周/季度 |
| 发现与评估 | 值不值得追 | 价值假设卡、基线-目标、成本定价模型 | 假设裁定周期、立项后偏差率 | 双周/按需 |
| 工程执行 | 如何真正跑起来 | ADR、Backlog、证据包 | Lead Time、TtV、流速效率 | 周/Sprint |
| 组织学习与资产 | 下次如何更省力 | 资产登记簿、模式库、复用说明书 | 复用率、资产验证率 | 月/季度 |

- **三条回路**：快（周级 Sprint，只改执行方式）/ 中（月级 G3，改价值假设）/
  慢（季度，改资源配置）。只有快回路会表现为「交付很稳、方向长期错」。
- **接口契约五条（§6.3）**：只认制品、不认口头承诺，任一条不满足下游有权拒收——
  机会卡（客户主体+价值量级+战略归属）→ 价值假设卡+基线-目标+可行性+成本定价（G1）→
  证据包（G2，且具备可测基线）→ 价值实现报告（基线 vs 实际，**非满意度评分**）→
  资产条目（跨场景复现 + owner + 版本，G4）。
- **5 vs 11 不是矛盾**：本节按项目主循环数得 5 个里程碑式交接；§5.2.2 按流数（含回流）得 11 个。
  做接口契约按 5（少而重），排查损耗断点按 11（全而细）。

## 8. 主循环、五道门禁与铁律（§11）

```
① 组合选择 [G0] → ② 发现验证 [G1] → ③ 工程实现 [G2]
→ ④ 采纳与价值实现 [G3，由发现与评估裁定] → ⑤ 知识捕获与资产化 [G4]
→ ⑥ 证据回灌组合管理 / 发现与评估（回到 ①）
```

| 门 | 准入证据 | 裁定权 | 未通过处置 |
|---|---|---|---|
| **G0** 组合门 | 机会卡（客户主体 + 价值量级 + 战略归属） | 组合管理负责人 | 退回补全 / 不入组合 |
| **G1** 立项门 | 问题证据 ≥2 源、基线-目标可测、可行性达标、成本定价闭合 | 立项评审会 | No-Go / Hold / 有条件 Go |
| **G2** 工程门 | 工程八项质量证据 + 回滚预案 | 质量责任人 | 退回修复，不得部署 |
| **G3** 价值门 | 基线 vs 实际对照（≥30 天）、业务质量六项 | **发现负责人 + 客户** | 假设修正 / 缩减范围 / 终止 |
| **G4** 资产门 | 跨 ≥2 场景复现、适配清单、owner、版本与 SLA | 资产评审会 | 降级为参考模式 |

- **一条铁律**：**价值由独立于交付方的人用基线对照裁定，不由交付方自证**（§11.1 注④）。
- 节奏：机会随到随评 / 组合排序双周 / G1 双周按需 / Sprint 2 周 / G3 上线后 30·60·90 天 /
  G4 月度 / 价值流再建图季度 / 组合季度复盘。
- **§11.4 防局部最优**（配平指标）：机会数↔终止及时率与组合价值密度；立项速度↔立项后偏差率与
  **无基线立项数（应恒 0）**；吞吐/利用率↔TtV、流速效率、缺陷逃逸率；资产数/复用次数↔
  复用价值贡献、A3+ 占比。任一指标成为考核项就会被优化到失真，配平指标让失真立刻可见。

## 9. 一页速查（§13 压缩）

- 三流：价值流=做什么有价值 / 工作流=怎么执行 / 资产流=怎么变强。
- 19 个处理步落 4 子系统（组合 1 / 发现 5 / 工程 6 / 组织学习 7）；**唯一三流交汇处是工程执行**，
  故 G1/G2/G3 设在交汇点而非子系统内部。
- 五道门 G0–G4；三条回路快/中/慢；一条铁律（价值不由交付方自证）；
  一条警告（三流不可同指标考核、资产化必须预置预算）；
  一个陷阱（把三流当部门传棒 → 漏掉全部回流，资产流退化为归档、反向裁定退化为返工）。
