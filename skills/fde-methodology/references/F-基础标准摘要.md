## 1. 定义与概念边界（§1、§3、§4.1、§19）

- FDE = 前沿部署工程（Forward Deployed Engineering），**以客户价值为中心的工程经营模式**；
  把工程能力部署到贴近客户真实运营的位置，将业务理解、工程实现、运营采纳与可衡量成果连成一体。
- 根本目标：**通过工程化手段，将真实的客户问题转化为可衡量的业务改善**（§1）。
- 不是：传统咨询、系统集成、人员补充、纯数据工程、AI 原生开发、项目管理、产品开发（§3.1–3.7）。
- AI 降低实现成本，但**不自动解决**问题发现、业务情境、系统集成、运营采纳与价值验证（§2.4、§13.4）。
- 核心模型一句话：**项目组织的是工作；价值流组织的是客户价值的流动**（§3、§19.2）。

## 2. 三流与四子系统（§4、§5、§11.6、§14）

| 流 | 目的 | 主要关注 |
|---|---|---|
| 价值流 Value Stream | 客户需求 → 已实现的价值 | 端到端客户成果 |
| 工作流 Work Flow | 组织并执行工程工作 | 工程交付与验证 |
| 知识与资产流 | 经验 → 可复用能力 | 组织学习与杠杆效应 |

- 三条流**彼此独立、相互强化**：价值流给出理由，工作流给出机制，资产流提升未来效能（§4、§11.6）。
- **资产流是组织学习机制，不是另一条客户价值流**（§4、§11.1）。

| 子系统 | 管理职责（§5、§14.1–14.5） |
|---|---|
| 组合管理 | 机会选择、优先级、产能、投资与治理、暂停与终止 |
| 发现与评估 | 问题验证、客户情境、价值假设、基线与目标、可行性、成本与定价、商业风险 |
| 工程执行 | 架构、WBS/待办、Sprint、质量、测试、部署、证据、运营过渡 |
| 组织学习与资产 | 知识捕获、模式识别、资产验证、复用、版本、所有权、产品化 |

- 主循环（§5、§14.6）：**选择机会 → 验证价值 → 执行工程 → 实现客户价值 → 捕获学习 → 改进未来决策**。
- 四子系统**不是四条独立的价值流，也不是互不联通的部门**（§14.1）。

## 3. 客户价值（§5）

- **价值必须站在客户视角定义**（§5.1），七类维度：财务 / 运营 / 质量 / 风险 / 决策 / 能力 / 体验。
- **价值必须可观测**（§5.2）：主张须含业务问题、预期运营改善、可度量结果、系统边界；
  「实施一个 AI 排程平台」是弱主张，「把排程调整时间从数小时降到 30 分钟内」才是强主张。
- **价值假设**（§5.3）七要素：当前状况、约束/问题、预期改善、工程干预、度量方法、假设与风险、预期周期。
  价值假设是可检验陈述，**不是保证**。
- **三态**（§5.4）：基线 Baseline（干预前实测）/ 目标 Target（预期）/ 实测 Actual（实现后实测）；
  实测决定假设「达成 / 部分达成 / 被证伪」。
- **§5.5 交付验收 ≠ 价值实现**（硬约束）：前者验证交付物是否符合验收标准，后者验证客户是否获得
  预期业务改善；已通过功能验收却未产生改善的原因包括未采纳、数据质量、流程未变、未触及真约束、
  外部条件变化。**两者都必须保持可见。**

## 4. 价值流（§6）

- 七活动（§6.2）：客户需求 → 发现 → 价值定义 → 方案设计 → 工程与交付 → 采纳与运营 → 价值实现
  →（反馈与改进回到发现）。**这是概念地图，不是强制线性 stage-gate**；真实价值流含迭代、并行、
  返工、重新评估、等待、外部依赖与运营反馈回路。
- **§6.4 价值流不是项目生命周期**（本框架最重要的边界）：

| 维度 | 项目生命周期 | 价值流 |
|---|---|---|
| 视角 / 管理单元 | 项目管理 / 项目·里程碑·任务 | 客户价值 / 端到端价值流 |
| 起点 → 终点 | 项目授权 → 完成或验收 | 客户需求或机会 → 实际价值实现 |
| 关注 | 范围、时间、成本、质量 | 流动、等待、瓶颈、成果 |
| 反馈 / 改善目标 | 围绕评审组织 / 项目绩效 | 连续运营反馈 / 客户价值流动绩效 |

  单条价值流可跨多个项目；一个项目可只改善其中一段；**项目完成未必意味着价值实现**。
- §6.5：组合回答「追哪些机会、资源投向哪里」；价值流管理回答「价值如何流动、哪里等待、
  什么约束交付」。**组合不能替代价值流管理。**

## 5. 精益与流动（§7、§8）

- §7.1 从流程管理转向流动管理；§7.4 **流动重于利用率**（高利用率使队列、等待、切换增加）；
  §7.5 拉动重于推动；§7.6 持续改进。
- §7.2–7.3 增值 / 必要非增值 / 浪费与八类浪费是**定性 VSM 分析框架**，不是可录入字段。
- §8 VSM：现状图（活动/交接/决策点/系统边界/信息流 + 每步处理与等待时间）→ 未来态图
  → 改进原则；§8.5 明确 **VSM 是管理工具**，不是又一套报表。

## 6. 工作流（§10）

- §10.1 工作流 ≠ 价值流：前者由工程活动与依赖定义，后者由客户价值定义。
- §10.2 典型十步：机会与问题定义 → 发现与技术调查 → 架构设计 → 待办分解 → Sprint 规划 →
  实现 → 测试验证 → 部署 → 运营验证 → 文档与知识捕获（可重复或并行）。
- §10.3 **Sprint 是执行机制，不是客户价值边界**：合格产出是「已验证技术假设 / 可运行集成 /
  可部署能力 / 运营改善 / 可度量瓶颈削减」之一，而非「计划任务全勾完」。
- **§10.4 工作项可追溯性（六锚点）**：客户问题或机会 / 价值假设或运营需求 / 价值流活动 /
  技术或运营成果 / DoD / 验证证据。防止工程工作与客户价值脱节。
- §10.5 工作流内四道质量门：问题验证门 → 方案就绪门 → 交付质量门 → 价值实现门；
  **质量门应保护价值实现，而非制造额外审批队列**。

## 7. 度量（§9、§16）

- **§9.1 表列 9 项**（上游文档行文中称「八个基础指标」，本摘要按表格实际列示计）：

| 指标 | 定义要点 |
|---|---|
| End-to-End Lead Time | 已定义起始 → 完成事件的流逝时间 |
| Process Time | 实际执行耗时（**不等于人力投入**） |
| Waiting Time | 未实际推进的耗时 |
| Flow Efficiency | Process ÷ Lead Time（§9.4 分子分母同边界） |
| WIP | 边界内已启动未完成事项数 |
| Throughput | 单位时间完成项数 |
| Rework Rate | 需重复修正的工作占比 |
| Time to Value (TTV) | 需求/机会事件 → **首个已验证**价值事件 |
| Value Realization Rate | 已验证假设中达成目标的比例 |

- **§9.2 指标定义必须明确**：起点、完成、自然日/工作日基准、客户等待、外部依赖、覆盖范围
  六项缺一不可；定义与数字必须同屏。
- **§9.3 TTV ≠ Lead Time**，禁止互换；一条价值流可有多次价值增量，首次 TTV 与后续间隔分开计量。
- §9.4 流动效率剩余时间**不自动等同于浪费**；§9.5 指标必须平衡（流动、工程质量、客户价值、
  运营稳定性、经济绩效、风险与合规六方面），优化单一指标会引发不良行为。
- §16.1 均衡度量五维：客户价值 / 流动绩效 / 工程质量 / 经济绩效 / 组织能力；
  §16.2 领先指标（预测）与滞后指标（已取得成果）都要用。
- **§16.3 防指标博弈**：Sprint 速度不作生产力排名、高利用率不证明效率、交付特性数不等于客户价值、
  资产数量不等于复用有效性、满意度不替代客观运营证据。指标支撑诊断，**不替代专业判断**。

## 8. 双维质量（§15）

| 维度 | 要素 |
|---|---|
| 工程质量 | 正确性、可靠性、安全性、可维护性、性能、集成完整性、可测试性、运营就绪度 |
| 业务质量 | 问题相关性、价值假设有效性、工作流适配性、用户采纳、运营有效性、可度量业务成果 |

- **§15.2 两道门互补且不可互相替代**：工程质量门（技术上是否安全、正确、可维护）与
  价值质量门（是否解决已验证问题并产生预期客户价值）。
- §15.3 治理应确立决策所有权、客户责任、安全合规、架构边界、数据治理、证据要求、变更管理、
  运营问责、资产所有权；**治理应降低风险，不制造不必要的等待与交接**。

## 9. 知识与资产流（§11）

- §11.3 八类资产：领域知识 / 问题模式 / 方案模式 / 技术组件 / 运营资产 / AI 资产 / 交付资产 / 产品能力。
- §11.4 学习回路：客户合作 → 一线证据 → 知识捕获 → 模式验证 → 资产开发 → 复用 → 改进；
  **并非每个项目实现都应变成资产**；评估八项：可重复性、稳定性、跨客户适用性、维护成本、
  安全性、配置灵活性、所有权、可度量复用价值。
- §11.5 产品化由**已证实的重复性与价值**驱动，而非把每个客户实现变成产品的冲动。

## 10. 十四原则（§17，规范化基础）

价值优先 · 客户情境 · 先问题后方案 · 成果重于产出 · 端到端思维 · 流动重于利用率 ·
拉动重于推动 · **证据重于状态** · 双维质量 · 持续改进 · **复用而不丢失情境** ·
AI 作为倍增器 · 经济可持续性 · 组织学习。

## 11. 成熟度、AI 与经济（§12、§13、§18）

- §18.2 成熟度 L1–L6 原文自述为 "a maturity framework, **not mandatory organizational stages**"，
  允许不同业务域处于不同等级。
- §13 AI as a Multiplier 是**关于 AI 作用的论断，不是可观测事实**；§13.3 人与 AI 的责任不可转移。
- §12.5 商业模型（订阅等）属经营层口径；§12.6 商业激励必须与价值流行为对齐。

## 12. §20 层级约束（引用纪律）

- 基础标准定义 **why / what**；四册方法论定义 **how**（Portfolio / 立项评估 / Sprint 执行 /
  组织学习与资产）。
- **四册不得各自重新定义客户价值、价值流边界或 FDE 的基本含义**；所有操作标准须与本文价值流一致。
- 本仓的 SKILL.md、对齐说明与所有摘要同受此约束：**不得用下游口径反推上游定义**。
