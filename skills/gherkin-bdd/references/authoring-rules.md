# Gherkin 编写规范（Capability Twin 方言）

> 适用对象：所有 `features/**/*.feature`。`scripts/gherkin_gate.py` 是本规范的**可执行判定器**，
> 规范条文与校验码一一对应；人工评审不得绕过 `validate` 的结果。

## 1. 方言与关键字

文件**第一行**必须是 `# language: zh-CN`（`BDD-001`）。统一使用下表左列，禁止英文关键字（`BDD-002`）。

| 结构 | zh-CN 标准写法 | 禁止的英文写法 |
|---|---|---|
| 功能 | `功能:` | `Feature:` |
| 规则 | `规则:` | `Rule:` |
| 背景 | `背景:` | `Background:` |
| 场景 | `场景:` | `Scenario:` |
| 场景大纲 | `场景大纲:` | `Scenario Outline:` / `Scenario Template:` |
| 例子 | `例子:` | `Examples:` / `Scenarios:` |
| 前置 | `假如 ` / `假设 ` | `Given ` |
| 动作 | `当 ` | `When ` |
| 结果 | `那么 ` | `Then ` |
| 承接 | `而且 ` / `并且 ` / `同时 ` | `And ` |
| 转折 | `但是 ` | `But ` |
| 通配 | `*` | `*` |

- 关键字后必须有**一个半角空格**（`假如 `），冒号后必须有空格；步骤文本不得为空（`BDD-018`）。
- 中文全角冒号 `：` 不接受；表头分隔符用 `|`；`#` 起始行为注释。
- 迁移期可用 `validate --allow-en` 将英文关键字降级为 `warning`，但**不得**用该开关提交新场景。

## 2. 文件与结构

```gherkin
# language: zh-CN
@ct-module=account                     # Feature 级标签：作为本文件全部场景的默认值
功能: 发出商品的收入与成本配比
  作为 财务负责人
  我希望 发货未开票时收入暂不确认、成本随发出商品归集
  以便 符合中国企业会计准则的配比要求

  背景:
    假如 账套「华东公司」已启用中国企业会计科目表
    而且 会计期间「2026-11」已打开

  @ct-id=SCN-ACC-001 @ct-unit=CU-ACC-014 @ct-gate=G2
  场景: 发货未开票时确认发出商品
    假如 销售订单「SO-001」已确认，商品「A」的可用量为 10 件
    当 仓库按订单发货，发出商品「A」10 件且尚未开票
    那么 该批商品计入「发出商品」10 件
    而且 当期主营业务收入不含该批商品金额 1200 元
```

- 功能描述建议包含 `作为 / 我希望 / 以便` 三段；缺失为 `warning`（`BDD-017`）。
- `背景` 只放**所有场景共有**的前置条件；不得放动作或断言。
- 一个 `功能` 至少一个 `场景`；一个 `场景` 至少一条 `当` 和一条 `那么`，`假如` 可由 `背景` 提供（`BDD-005`、`BDD-011`）。
- `背景` 的步骤计入所有场景的执行序列（用于前置条件判定），但不计入场景自身的步骤数。
- 缩进使用 2 空格层级；`例子` 数据表用 `|` 对齐。

## 3. 标签体系

| 标签 | 级别 | 必填 | 说明 |
|---|---|---|---|
| `@ct-id` | 场景 | 是 | `SCN-<域>-<3位序号>`，如 `SCN-ACC-001`；全局唯一（`BDD-004`、`BDD-013`） |
| `@ct-unit` | 场景 / 功能 | 是 | 关联能力单元，如 `CU-ACC-014` |
| `@ct-module` | 功能 / 场景 | 是 | 与 `features/<module>/` 目录名一致（`BDD-014`） |
| `@ct-gate` | 场景 / 功能 | 是 | `G2`（工程完成，自动化可判定）/ `G3`（业务验收，人工裁定） |
| `@ct-source` | 场景 / 功能 | 否 | 源码证据相对路径，行号用 `:` 分隔，如 `addons/account/models/account_move.py:L128` |
| `@ct-priority` | 场景 | 否 | `P0` / `P1` / `P2` |
| `@ct-risk` | 场景 | 否 | 合规/资金/税务等风险标记 |

规则：
- 功能级标签由本文件全部场景**继承**；场景级同名标签**覆盖**功能级值。`@ct-id` 禁止写在功能级。
- 标签值只允许 `[A-Za-z0-9._=/:-]`，禁止空格与 `#`（`BDD-010`）。
- 缺少任一必填标签判 `error`（`BDD-003`）；缺 `@ct-source` 判 `warning`（`BDD-019`），因为证据可由追溯矩阵后补。

## 4. 步骤纪律

| 关键字 | 语义 | 写法要求 |
|---|---|---|
| `假如` | 已成立的业务事实 | 用完成态「已…」；只描述状态，不描述操作 |
| `当` | **一个**业务动作 | 一个场景一条 `当`；多条为 `warning`（`BDD-012`） |
| `那么` | 可观察、可断言的业务结果 | 必须含数量/金额/状态/科目等可判定事实 |
| `而且 / 但是` | 承接上一步的同类语义 | 不得用于引入新的业务动作 |

- 步骤文本使用 [统一语言词表](ubiquitous-language.md) 的标准业务词；禁用别名与技术黑话判 `error`（`BDD-007`）。
- 禁止「系统正常」「操作成功」「符合预期」「正确显示」等不可判定表述，判 `warning`（`BDD-015`）。
- 同一场景内完全重复的步骤文本判 `warning`（`BDD-016`）。
- `那么` 之后不得再出现 `当` 或 `假如`；`当` 之后不得再出现 `假如`（`BDD-006`）。
- 步骤只写业务，不写点击路径、控件、页面元素；UI 细节属于步骤定义（step definition）实现，不属于规格。

## 5. 数据与参数化

- 同一场景需在多组数据上重复验证时使用 `场景大纲` + `例子`。
- `<占位符>` 必须与 `例子` 表头**完全闭合**：表头出现而步骤未使用、步骤使用而表头缺失，均判 `error`（`BDD-008`）。
- `例子` 表至少一行数据，且每行列数与表头一致（`BDD-009`）。
- 表头使用中文标准业务词；数据值可含数字、`「」` 包裹的业务对象名称。
- 多行结构化业务数据用 `|` 数据表；长文本证据用 `"""` DocString；两者都不得承载技术参数（连接串、XML ID、模型名）。
- 场景必须可独立执行：不依赖其他场景的执行顺序或残留数据。

## 6. 校验码表

| 码 | 级别 | 含义 |
|---|---|---|
| BDD-001 | error | 缺少 `# language: zh-CN` 声明 |
| BDD-002 | error | 使用英文关键字（`--allow-en` 时降为 warning） |
| BDD-003 | error | 缺少必填标签 |
| BDD-004 | error | `@ct-id` 重复 |
| BDD-005 | error | 场景缺 `假如` / `当` / `那么` |
| BDD-006 | error | 步骤关键字顺序违规 |
| BDD-007 | error | 禁用别名或技术黑话 |
| BDD-008 | error | 占位符与 `例子` 表头不闭合 |
| BDD-009 | error | `例子` 表结构或数据行异常 |
| BDD-010 | error | 标签值含非法字符 |
| BDD-011 | error | 功能无场景 / 场景无步骤 |
| BDD-012 | warning | 单场景存在多个 `当` |
| BDD-013 | error | `@ct-id` 格式不合法 |
| BDD-014 | warning | `@ct-module` 与目录名不一致 |
| BDD-015 | warning | 结果不可判定或步骤文本过短 |
| BDD-016 | warning | 同一场景内重复步骤 |
| BDD-017 | warning | 功能描述缺业务价值三段式 |
| BDD-018 | error | 无法解析的结构或空步骤文本 |
| BDD-019 | warning | 场景缺 `@ct-source` 源码证据 |
| BDD-020 | error | 目标目录未发现任何 `.feature` 文件（防止空目录假绿） |

`error` 使 `validate` 返回退出码 `1`；`warning` 只记录不阻断。不设分数、不设等级。

## 7. 反模式

| 反模式 | 问题 | 正确做法 |
|---|---|---|
| 在步骤里写 `account.move` 状态 | 技术黑话，业务方无法评审 | 写「会计凭证已过账」 |
| UAT 表格手工另写一套步骤 | 两份事实源必然漂移 | 由 `uat` 子命令从 `.feature` 生成 |
| `当` 里连写「确认订单并发货并开票」 | 场景边界模糊，失败无法定位 | 拆成多个场景 |
| `那么 系统正常工作` | 不可断言，自动化只能假绿 | 写数量/金额/科目的具体值 |
| 把价值指标写进 G2 场景 | 混淆工程完成与价值实现 | 价值三态另记，见 FDE 2.0 §5.3–5.5 |
| 生成步骤桩后即宣称测试通过 | 桩显式抛错，执行必然失败 | 以外部 runner 结果作为 G2 证据 |

## 8. 提交前清单（DoR）

1. `python3 .../gherkin_gate.py validate <features_dir>` 退出码 `0`，`issues` 中 `error` 为 0。
2. 每个场景有唯一 `@ct-id`，且 `@ct-unit` 能在能力单元规范中找到对应条目。
3. 场景文本已由业务方确认，术语与词表一致，无技术黑话。
4. `matrix` 生成的追溯矩阵与 `uat` 生成的用例编号一致。
5. G3 场景已标明人工裁定人；G2 场景已接入外部 runner 或有明确未接入说明。
