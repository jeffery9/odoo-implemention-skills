# 统一语言词表（Ubiquitous Language Glossary）

> 本表是**业务术语的唯一裁决依据**。`.feature` 场景文本只能使用「标准业务词」列；
> 「Odoo 业务对象」列仅供开发实现与源码追溯使用，**不得写入场景文本**。
> 与 `static/description/index.html` 一类对外展示页不同，本表是内部工程资产，允许出现对象名。

## 1. 使用规则

1. 一个业务概念只能有一个标准词。右列「禁用别名」在任何 `.feature` 中出现即判 `BDD-007`。
2. 标准词在 `假如 / 当 / 那么` 中写法完全一致，不得加修饰、缩写或中英混写。
3. 数量、金额、日期一律写成可断言的字面值或 `<占位符>`，不写「若干」「适当」「稍后」。
4. 新增术语必须同时登记：标准词、含义、Odoo 业务对象、禁用别名、登记人、登记日期；
   未登记的词不得进入场景文本。词表变更需人评审，不由运行时自动改写。

## 2. 销售与应收

|---|---|---|---|

## 7. 技术黑话禁用清单（场景文本不得出现）

命中以下任一类即判 `BDD-007`：

- **对象名模式**：形如 `小写字母.小写字母` 的 Odoo 模型名（`account.move`、`stock.picking`、`mrp.production`、`sale.order`、`res.partner`、`ir.rule`、`res.groups`、`ir.model.access`…）。
- **字段名/方法名模式**：`partner_id`、`product_id`、`state`、`amount_total`、`_compute_*`、`create()`、`write()`、`@api.depends`、`button_validate`。
- **UI/自动化实现词**：`click()`、CSS 选择器、`xpath`、`XML ID`、`menu_id`、`view_id`、`selector`。
- **内部框架词**：`capability unit` 编号写进业务句子、`Sprint`、`SEC-` 契约号、版本号迭代史、测试数量等元数据（元数据一律放标签或矩阵，不进步骤文本）。

> 例外：`@ct-module=account` 等标签值、`<占位符>` 名称、数据表表头允许使用 ASCII 标识符；
> 业务句子本身必须保持纯业务语言。

## 8. 与能力单元的绑定

`@ct-unit` 引用的能力单元在 `CAPABILITY_UNIT_SPEC.md` 中必须以 `{{test_scenario_feature}}` 指向对应 `.feature` 路径，
不得在规范正文里再抄一遍步骤。追溯链为：

```
业务术语（本词表） → .feature 场景（@ct-id） → 能力单元（@ct-unit） → 源码证据（@ct-source） → 自动化结果（G2）
```
