# 证据分级

## 1. 三态就绪度

| 状态 | 含义 | 谁能判定 |
|---|---|---|
| `implemented` | 代码/配置已就位，自动化检查通过 | 机器（G2） |
| `verified` | 场景在目标环境执行通过 | 机器 + 顾问复核（G3） |
| `valuable` | 业务方确认价值实现 | 人（FDE 2.0 §5.5） |

顺序单向：未达 `implemented` 不得声称 `verified`；未达 `verified` 不得声称 `valuable`。契约校验通过只支撑第一态。

## 2. 证据等级

| 等级 | 证据 | 可信度 |
|---|---|---|
| E1 | 契约字段声明（本包 schema 校验） | 最低：只证明「声明了什么」 |
| E2 | 静态检查（结构、标签、术语） | 证明「格式正确」 |
| E3 | 场景派生（UAT、步骤桩、矩阵） | 证明「场景被覆盖」 |
| E4 | 目标环境执行结果 | 证明「在真实环境跑通」 |
| E5 | 业务方签字验收 | 最高：证明「价值被认可」 |

本包的 `validate_odoo_manifest.py` 产出 E1/E2 级证据；它**不能**产出 E4/E5。任何把 E1/E2 报告为「验收通过」的说法都是证据越级。

## 3. 与现有结论一致

README 与 `gherkin-bdd/SKILL.md` 已声明：

> 自动化通过 = 工程完成（G2）；交付验收 ≠ 价值实现（FDE 2.0 §5.5）。

本包不改变这一结论。新增的 Odoo 契约校验是 G2 的辅助证据，不是 G3 的替代。
